NETWORKING NOTES
================

TCP/IP Fundamentals
-------------------
TCP (Transmission Control Protocol) provides reliable, ordered, error-checked delivery
of a stream of bytes between applications over an IP network.

The TCP three-way handshake establishes a connection:
  1. SYN   — client sends a segment with SYN flag set, picks initial seq number.
  2. SYN-ACK — server acknowledges client's SYN and sends its own SYN.
  3. ACK   — client acknowledges server's SYN; connection is now established.

Connection teardown uses a four-way FIN/ACK exchange.

Key TCP concepts:
  - Sliding window: allows multiple unacknowledged segments in flight.
  - Congestion control: slow start, congestion avoidance, fast retransmit (TCP Reno/Cubic).
  - Nagle's algorithm: coalesces small writes to reduce packet count.
  - TIME_WAIT state: 2*MSL (Maximum Segment Lifetime) after close — prevents stale packets.

UDP (User Datagram Protocol) is connectionless, no delivery guarantee, lower overhead.
  Suitable for: DNS, VoIP, video streaming, online games.

HTTP/1.1 vs HTTP/2
------------------
HTTP/1.1 (1997):
  - One request per TCP connection (pipelining is unreliable in practice).
  - Head-of-line blocking: later requests wait for earlier ones in the same connection.
  - Headers sent as plain ASCII on every request — repetitive, verbose.
  - Keep-Alive header allows connection reuse across multiple request/response cycles.

HTTP/2 (2015, RFC 7540):
  - Multiplexing: many requests/responses share a single TCP connection concurrently.
  - Binary framing layer: frames instead of text, more efficient parsing.
  - Header compression (HPACK): dynamic table eliminates redundant headers.
  - Server push: server can proactively send resources the client will likely need.
  - Stream prioritization: clients can hint at relative importance of resources.
  - Still suffers from TCP head-of-line blocking (solved in HTTP/3 via QUIC/UDP).

HTTP/3 (2022, RFC 9114):
  - Runs over QUIC (UDP-based), eliminates TCP head-of-line blocking entirely.
  - Independent streams: packet loss in one stream does not stall others.
  - Faster connection establishment: 0-RTT or 1-RTT handshake.

TLS Handshake (TLS 1.3)
------------------------
TLS 1.3 simplified the handshake to 1-RTT (down from 2-RTT in TLS 1.2):

  Client Hello  → server  (supported cipher suites, key_share, random nonce)
  Server Hello  → client  (chosen cipher, key_share, certificate, Finished)
  Client Finished → server (derives symmetric keys, starts sending encrypted data)

Key improvements in TLS 1.3:
  - Removed weak cipher suites (RSA key exchange, CBC mode ciphers, SHA-1, MD5).
  - Forward secrecy is mandatory: ephemeral Diffie-Hellman (ECDHE) for key exchange.
  - 0-RTT resumption for returning connections (replay attack risk must be managed).

Certificate validation:
  - Server presents X.509 certificate signed by a CA in the client's trust store.
  - Client verifies: chain of trust, expiry date, hostname (SAN/CN), revocation (OCSP).

Common ports: HTTP=80, HTTPS=443, SSH=22, SMTP=25, DNS=53, PostgreSQL=5432.
